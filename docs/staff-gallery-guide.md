# 装着事例の更新方法

## 最初の設定

登録画面は公開ギャラリーのURLに `/admin/` を付けた場所にあります。ChatGPTでログインしてください。管理者は「スタッフ管理」で、各スタッフがChatGPTにログインするメールアドレスを登録します。

- 登録担当：写真と情報の登録、下書き保存、確認依頼。
- 公開担当：上記に加えて公開・取り下げ。
- 管理者：上記に加えてスタッフの追加・権限変更。

スタッフ登録はメール送信を伴いません。登録画面のURLを社内で共有してください。futureshopのログインとは別です。

## 新しい写真を追加する

1. 「新しい事例を登録」を押す。
2. 同じ車種・同じシリーズの装着写真を選ぶ。30枚まで。先頭の写真が表紙。
3. 車種・ブランド・シリーズを入力。色名は商品の正式名称を入力し、検索用の色系統を別に選ぶ。
4. 掲載品番を入力。「掲載型式」は投稿に明記された車両型式だけを入力し、グレード・仕様などは「掲載車両情報」に分ける。型式が不明なら空欄にする。コメントを載せる場合は許諾を確認する。
5. 「下書きを保存」。途中でも保存でき、ほかのPCから続けられる。
6. 写真の対応、色の分類、掲載許諾と個人情報を確認し「確認を依頼」。
7. 公開担当がプレビューを確認して「確認して公開」。Sitesの公開ギャラリーにすぐ反映される。

写真はアップロード時に長辺2,000px以内のJPEGへ変換し、撮影位置などの画像メタデータを引き継ぎません。人物の許諾やナンバープレートなどの写り込みはスタッフが確認してください。原本は社内写真フォルダーで管理します。

## 既存の事例を修正する

「公開中の事例を編集」で車種やシリーズを検索し、写真を確認して「編集する」。公開済みの内容は、新しい修正を公開するまでそのまま表示されます。「公開を取り下げる」で一覧から非表示にできます。下書きと写真は削除されません。

別のスタッフが先に保存したときは、上書きせずエラーを表示します。自分の入力を控え、最新版を開き直して変更を合わせてください。

## 商品リンクと適合

商品URLは `https://seatcover.jp/c/…` の商品ページを入力します。公開時にページの応答と掲載品番の選択肢を照合します。確認できない場合は公開を止めます。URLを空欄にすれば、公式適合表で商品を探す案内に切り替えて公開できます。

掲載品番・車種・ブランドが、取り込んである適合マスターに一致する場合だけ掲載条件を表示します。マスターは公開中の全品番を保持し、既存・新規の事例へ現在の条件を反映します。新しい適合品番は適合マスターCSVの更新も必要です。担当者は `npm run sync:fitment -- "CSVの保存先"` を実行し、確認後にコードとマスターを反映します。日々の事例追加と、適合マスターの更新は別の作業です。

条件には適合車種・年式範囲・型式・グレード・定員を表示します。ハイエースなどの総称でも、条件内では「バン」「ワゴン4列」を区別します。この条件を投稿者の実車仕様として補うことはありません。年式は開始のみなら「2025/11 ～」、終了のみなら「～ 2025/10」と表示します。在庫や個々のお客様の実車適合を保証するものではありません。

カングーの表示名は「ルノー カングー」に統一します。以前の「カングー」で検索しても同じ事例が表示されます。正式色名と色系統は別に確認し、チャコールグレーを含む事例はグレー系からも探せるようにします。

## 月1回のメール取り込みとお客様レビュー

装着メールの本文・写真を取得し、ネクストエンジンの受注CSVと照合して共有下書きへ登録する作業は、月1回行います。次回は「月次の装着メール登録」と依頼すれば、過去のメールIDと登録台帳を照合して追加分を処理します。毎回の写真保存操作を省く設定と、原本を専用フォルダーへ整理する手順を引き継いでいます。

詳しい社内手順は `.source/mail-intake/MONTHLY_WORKFLOW.md`。受注CSVの期間は実際の購入日と未照合分に合わせます。未確認の写真・色系統・許諾は、下書き登録後にスタッフが確認します。

ギャラリーの「お客様の装着レビュー」では、公開済みで感想のある事例だけを表示します。カードを押すと、写真と掲載コメントを読めます。新しい事例の感想も、確認して公開した後に一覧へ反映されます。このレビュー表示は2026-10-05時点ではローカル確認版です。

掲載コメントは、メールの感想欄をそのまま転載せず、内容の意味を保って読みやすく整えます。表記・句読点・改行を整理し、注文番号の説明、プレゼントの希望、ブログ掲載予定などの連絡事項や重複文を分けます。取付けの苦労、説明書への不満、気になる点も残し、好評の文章へ書き換えないでください。写真・受注情報から感想を創作したり、お客様の発言にない内容を足したりしません。元の文章と整理後の文章は社内の台帳に保管します。編集した本文を「原文」「原文全文」と表示しないでください。

## 保存先・futureshop

共有データはSitesのD1、写真はR2に保存され、PC内のブラウザー保存には依存しません。日々の登録・公開にGit操作やデプロイは不要です。

今回の公開操作で反映されるのはSitesのリニューアル版です。seatcover.jpのfutureshop管理画面への自動アップロードは未接続です。「公開データを出力」で、公開版だけのJSONを取得できます。写真URLは出力時のサイトの絶対URLに変換します。futureshopへ移設する際は、登録画面の保存先を維持して公開APIを参照するか、出力データを移設先へ取り込む構成にします。URL変更やSites停止時は写真の移設も必要です。

## ローカルプレビュー

`/admin/` のローカルログインは確認用の模擬ログインです。画面上部に「ローカル確認用」と表示します。ローカルの下書き・写真は除外済みの `.preview/gallery-data/` に保存し、SitesやGitHubには送りません。本番ではプラットフォームの認証を使い、スタッフ権限を毎回確認します。

## 新しく追加した事例のNEW表示（2026-10-05）
新規事例は初回掲載から30日間、写真一覧・レビュー一覧の両方にNEWを表示します。初回掲載日時はサーバーの公開履歴から取得します。コメントの編集、再公開、非公開からの再公開では期間をリセットしません。既存ギャラリーの事例を編集しただけではNEWになりません。件数は表示対象の公開データから毎回計算し、全事例数・レビュー件数・新着件数に追加分を含めます。新着が0件ならNEW件数は表示しません。
