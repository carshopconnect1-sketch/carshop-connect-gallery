# 適合マスター連携（2026-09-25）

管理画面の「CSVダウンロード（全件）」から取得した `match-20260925.csv`（Shift_JIS、9,582行）を入力に、装着事例の掲載品番と照合した。元CSVのSHA-256は `49e8b96cbd16270c9aca361d918aad2605393119b897c5a36a892faf3cd0f8c1`。元CSVはローカルの Downloads にのみ置き、Git・Sitesには含めない。

同じブランド群・品番・車種名がすべて一致し、適合マスターで「表示」の行だけを採用する。事例2,895件のうちシートカバーは2,892件。写真に品番がある2,573件のうち1,937件を照合できた。319件は写真に品番なし、44件はマスター側の同品番なし、592件は車種名不一致。車種名不一致にはハイエース／ハイエース バン、N-BOX・N-BOXカスタム／N-BOXなどが含まれるが、車名だけで同一適合と決めない。これらは「不適合」判定ではなく未照合であり、公開画面にマスター条件を出さない。保留IDと理由は除外済み `.source/fitment-sync-audit.json` に記録する。

公開する `public/data/fitment.json` は事例ID・ブランド・車種・品番・掲載年式・年式開始／終了・型式・グレード・定員だけ。価格、特記事項、注意、備考、履歴、添付情報、非表示レコードは含めない。ビルド時にも列を検査する。詳細画面にはマスター取得日と、掲載年式／年式範囲の双方を示す。両者が異なる行もあるため、購入前に公式適合表で再確認する案内を維持する。販売状態・在庫・車両個体の最終適合はこのCSVだけでは確認できない。

更新時は適合マスターから再度「CSVダウンロード（全件）」を実行し、`npm run sync:fitment -- <CSVの絶対パス>`、`npm run check`、`npm test`、`npm run build` の順に実行する。これは静的スナップショットの更新であり、マスター変更の自動・即時反映ではない。前回より照合件数が大きく変わった場合は `.source/fitment-sync-audit.json` を確認し、原因が分かるまで公開しない。
